# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A teaching project for building a data platform on Databricks incrementally, using
Claude Code as the driver. The domain is a fictional B2B perfume distributor
("rota perfume"): sellers visiting stores, orders, payments, inventory, and CRM
opportunities. The real deliverable of each session is a working Databricks Asset
Bundle (DAB) under `rotaperfume/`, built up prompt by prompt.

- `dados/erp/` and `dados/crm/` — the 10 source CSVs (~313k rows, ~14.7 MB) that
  play the role of upstream systems. These land in a Unity Catalog Volume as the
  "raw" layer; nothing in `dados/` is generated by this repo, treat it as fixed
  input data.
- `rotaperfume/` — the Databricks Asset Bundle itself: raw (Volume landing +
  arrival-check), bronze (ingestion), silver (cleaning + contract), and gold
  (dimensions, `fato_vendas`, marts, quality tests) are all built as one
  growing `rotaperfume_pipeline` job. `resources/catalogo.yml` declares the
  bronze/silver/gold schemas and the `bronze.raw` managed volume;
  `scripts/criar-catalogo.sh` and `scripts/subir-raw.sh` handle the one-time
  catalog creation and raw file upload. Later `.llm/prompt-0N-*.md` sessions
  keep adding tasks/resources to this same bundle.
- `.llm/prompt-0N-*.md` — lesson scripts, one per session/deliverable. Each documents
  the exact prompt used to build that increment, the reasoning/gotchas to explain
  while it runs, and the SQL/CLI checks used to verify the result afterward.
  Read the relevant one before continuing work in `rotaperfume/` — it is the
  design spec, not just a training doc, and later prompts extend the same bundle
  rather than replacing it. These files come from a course repo with its own
  naming; before copying a command out of one, swap in this repo's own names
  (below) rather than running the file's literal names.
- `.databricks/`, `.claude/` — local tool state (aitools cache, plugin config).
  Not project source.

## Databricks environment

- This project uses the `rota-perfume` CLI profile. **Still pass `--profile`
  explicitly on every command** and don't assume; ask if it's ever ambiguous.
- `databricks.yml` variables: `catalog` (default `lakehouse_rotaperfume`),
  `warehouse_id` (default `869f5987fba5e50f`), shared by both `dev` (default
  target) and `prod` — one catalog, not one per environment.
- The workspace has Default Storage enabled at the account level, so the
  Unity Catalog API refuses `CREATE CATALOG` without an explicit managed
  location (`400 INVALID_STATE: Metastore storage root URL does not exist`).
  That's why the catalog is created out-of-band via `scripts/criar-catalogo.sh`
  (plain `CREATE CATALOG IF NOT EXISTS` over SQL) instead of as a bundle
  resource; schemas and the volume *are* bundle resources and deploy fine once
  the catalog exists.
- Before doing any Databricks-related work (auth, bundles, catalog/schema/volume
  setup, jobs), load the `databricks-core` skill first, then the matching
  product skill (e.g. `databricks-dabs`, `databricks-jobs`, `databricks-unity-catalog`).

## Common commands (run from `rotaperfume/`)

```bash
uv sync --dev                                                       # install deps
uv run pytest                                                        # run tests (needs Databricks Connect auth)
bash scripts/criar-catalogo.sh rota-perfume                          # one-time: create the catalog (see below)
databricks bundle validate --strict --target dev --profile rota-perfume
databricks bundle deploy   --target dev --profile rota-perfume
bash scripts/subir-raw.sh  rota-perfume                              # upload dados/erp + dados/crm to the raw volume
databricks bundle run rotaperfume_pipeline --target dev --profile rota-perfume
```

- Tests use `databricks-connect`/`databricks-sdk` and talk to a real workspace
  (see `tests/conftest.py`) — they fall back to serverless compute automatically
  if none is configured, but still require valid auth.
- `pyproject.toml` build backend is `hatchling`; the wheel packages `src`.
- Ruff line-length is 120 (`[tool.ruff]` in `pyproject.toml`).

## Conventions carried across sessions

- Unity Catalog objects (catalog/schemas/volumes) are defined as bundle
  resources (YAML), not clicked into existence — this is the whole point of the
  exercise. Any catalog-creation step that the UC API itself refuses (no
  managed storage location, see above) is done via a one-off SQL script
  outside the bundle, with the reason commented in the script.
- Do **not** set `mode: development` on the `dev` target if Unity Catalog schema
  names must stay stable — it prefixes resource names (including UC schemas)
  with `[dev <user>]`, which breaks hardcoded SQL. Pause schedules instead via
  `presets: { trigger_pause_status: PAUSED }`.
- Raw layer = files landed byte-for-byte in a Volume (`bronze.raw`); bronze
  layer = tables. Every raw-landing step is paired with an arrival-check step
  (row counts / byte sizes recorded to a control table) that fails loudly if a
  file is missing or empty — a silently-missing file produces a smaller number
  that still looks plausible, which is treated as the worse failure mode.
